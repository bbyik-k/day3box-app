# ADR-0001: 낙관 스토어 단일화 — 그리드 즉시 동기화

- **상태**: 채택 (2026-07-31)
- **관련**: Task 009.5 (커밋 `7c7068e`), [CHANGELOG 2026-07-31](../CHANGELOG.md#2026-07-31)

## 맥락

실사용 1일차에서 "TOP3의 색·소요시간을 바꿔도 타임 그리드가 한 박자 늦게 반영된다"는 피드백이 나왔다. 리전 정렬(함수 서울 고정)로 서버 왕복이 ~400ms까지 줄었지만, 그리드 갱신은 여전히 `서버 액션 → refresh() → 서버 재렌더` 왕복 후에만 일어났다.

원인은 지연 자체가 아니라 **낙관 상태의 분산 구조**였다:

- task 낙관 상태(색·분·승격)는 `PlanPanel`이, block 낙관 상태(이동·상태)는 `DayView`가 각자 소유
- 블록의 제목·카테고리는 **서버(page.tsx)에서 조인**된 `blockViews`로 내려옴 — 클라이언트가 색을 낙관 반영해도 블록이 참조하는 데이터가 아니라서 그리드에 나타날 방법이 없음
- 배치·배치 취소·이월은 낙관 반영이 아예 없었음 (배치는 슬롯 계산이 서버 전용 로직이었기 때문)

## 결정

1. **낙관 상태를 `DayView` 단일 스토어로 통합**: `useOptimistic({ tasks, blocks, carryTasks }, reducer)`. reducer의 각 액션은 대응하는 서버 액션의 결과를 미러한다 (task 삭제 → 블록 cascade 제거, 분 변경 → 블록 end_min 재계산, 승격 → 미사용 색 자동 지정 등).
2. **블록 뷰를 클라이언트 파생으로 전환**: 제목·카테고리를 낙관 tasks에서 조인한다 (서버 조인 제거). 색·제목·높이가 카드와 그리드에 동시에 반영되는 것은 이 파생의 자연스러운 결과다.
3. **배치 슬롯 탐색을 공용 함수로 추출**: `lib/grid.ts findNextFreeSlot` — 서버 `placeBlock`과 클라이언트 낙관 미리보기가 같은 코드를 사용한다. 로직 중복 없이 "미리보기 슬롯 = 서버 확정 슬롯"이 보장된다.
4. **서버는 계속 단일 진실**: 검증·거부(겹침, TOP3 제한, block 유무)는 서버가 담당하고, 클라이언트는 미리보기 + 즉시 피드백용 선검사만 한다. 서버가 거부하면 refresh의 rebase가 화면을 자동 정정한다. 서버 확정 전의 temp 블록은 조작(선택·드래그·삭제)을 차단한다.

`PlanPanel`은 프레젠테이션 컴포넌트로 축소됐다 (교체 모달 로컬 상태와 TOP3 하드 제한 선분기만 유지).

## 배제한 대안

- **(a) 서버 왕복 추가 단축만으로 대응**: 리전 정렬로 이미 물리적 하한 근처다. 왕복이 존재하는 한 "즉시"는 불가능 — 지연을 줄이는 것과 지연을 숨기는 것은 다른 문제.
- **(b) 분산 낙관 유지 + 그리드만 개별 패치**: 블록 제목·색의 조인이 서버에 있는 한, task 변경을 그리드에 반영할 통로가 없다. 패치를 거듭할수록 두 낙관 스토어 간 동기화 코드만 늘어난다.
- **(c) 전역 상태 라이브러리 도입**: 프로젝트 확정 규율 위반 (상태관리는 React 내장만 — PRD 5장). `useOptimistic` 하나로 충분함이 확인됐다.

## 결과

**긍정**
- 전 조작(색·분·배치·삭제·이월·상태)이 50ms 내 화면 반영 (E2E 실측, 프로덕션 확인)
- 데이터 흐름 단순화: "낙관 tasks가 곧 화면의 진실, 서버 확정이 곧 DB의 진실" 두 층으로 정리
- 슬롯 탐색 로직 중복 제거

**비용·주의**
- reducer가 서버 액션 규칙을 미러하므로, **서버 액션의 결과 규칙을 바꾸면 reducer도 함께 수정**해야 한다 (어긋나면 낙관 화면이 잠깐 거짓말을 하고 refresh가 정정하는 플래시 발생)
- temp 블록(서버 확정 전)은 즉시 조작할 수 없다 — 확정까지 ~400ms라 실사용 체감 없음
- 검증: Task 009.5 E2E 체크리스트 (즉시성 50ms assert + 새로고침 정합 + 기존 회귀)
