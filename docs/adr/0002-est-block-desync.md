# ADR-0002: est_min과 블록 길이의 비동기화 (양방향 동기화 롤백)

- **상태**: 채택 (2026-07-31)
- **관련**: Task 010, DECISION-BRIEF-002 미결 1번 · DECISION-BRIEF-003 §3, [ADR-0001](0001-optimistic-store-unification.md)
- **대체하는 결정**: 2026-07-29 "소요시간 ↔ 블록 높이 양방향 동기화" (Task 008.6)

## 맥락

Task 008.6에서 "분 수정 → 블록 리사이즈, 리사이즈 → 분 갱신"의 양방향 동기화를 구현했다. 당시 전제는 **task : 블록 사실상 1:1** — 하나의 소요시간 개념이 두 곳에 표시될 뿐이었다.

실사용 1일차에서 블록 분할(1 task : N blocks — 180분 작업이 점심으로 끊기는 매일의 케이스)이 필수로 확인되며 전제가 깨졌다. 블록이 여러 개면 "리사이즈가 est를 갱신한다"는 규칙은 성립하지 않는다(어느 조각이 진실인가?), "est 수정이 모든 블록을 리사이즈한다"는 규칙은 파괴적이다.

## 결정

**est_min과 블록 길이를 분리한다.**

| 값 | 의미 | 입력 수단 |
|---|---|---|
| `est_min` | **계획 총량** (어림값) | 칩(30/60/90/120/180) + ±10 스테퍼 — 자유 입력 없음, 10분 배수 |
| 블록 길이 합 | **실제 배치량** | 배치 + 그리드 리사이즈 (10분 스냅) |
| 차이 | **미배치 잔량** | — (배치 클릭 시 잔량이 다음 빈 슬롯에 배치됨 — Task 011) |

- 리사이즈는 `est_min`을 갱신하지 않는다. est 수정은 블록을 건드리지 않는다.
- 역할 분담: **좌측 칩 = 어림값 설정(배치 시작점), 우측 리사이즈 = 실제 조정.** 좌측에 정밀 입력을 두는 것은 기능 중복이다(D6).

## 배제한 대안

- **양방향 유지 + 분할 보류**: 분할은 "매일 발생하고 우회로가 없는" 1순위 마찰(브리프 §8.4) — 보류 불가.
- **조건부 동기화**(블록 1개일 때만 양방향): 블록 개수에 따라 동작이 달라져 예측 불가능. 규칙은 하나여야 한다.

## 결과

**긍정**: 분할의 데이터 전제 성립. "est=계획, 블록=실행"의 의미가 명확해짐. setEstMin·moveBlock 서버 액션과 낙관 reducer가 크게 단순해짐(겹침 연쇄 검증 제거).

**비용**: 단일 블록에서 리사이즈해도 카드의 분이 따라오지 않음 — 2일 만의 UX 반전이지만, "카드 분 = 계획, 블록 = 실제"로 의미가 재정의된 것 (Task 011의 `총 N분 · M분 배치됨` 표시가 이 관계를 시각화한다).

**주의**: ADR-0001의 reducer 미러 규칙에 따라 서버 액션과 낙관 reducer의 estMin·move 케이스를 함께 단순화했다.
