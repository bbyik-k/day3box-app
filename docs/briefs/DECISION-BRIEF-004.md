# Decision Brief #004 — Brain dump 행 재설계

> **읽는 순서**: `DECISION-BRIEF-002` → `DESIGN-DECISION-001` → `DECISION-BRIEF-003` → **이 문서**
> **범위**: 이번 사이클은 **D9까지**. D10(완료 표시)은 §3에 정의만 두고 구현하지 않는다.
> **성격**: 003에 없던 새 항목이다. 기존 brain dump 화면을 바꾸므로 002·003과 충돌하지 않는다.

---

## 0. 배경 — 무엇이 문제였나

실사용 중 발견: **일반 task를 타임박스에 배치하려 할 때 좌측 체크박스를 누르게 된다.** 그러나 체크박스의 실제 역할은 TOP 3 승격이다.

진단 세 가지:

1. **형태의 거짓말.** 사각 체크박스는 통념상 "완료"를 뜻한다. 그런데 이 제품의 완료는 저녁에 **블록 위에서** 기록한다. 같은 기호가 두 화면에서 다른 뜻이 된다.
2. **위치의 거짓말.** 행의 맨 왼쪽은 진입점인데, 거기 놓인 것은 **하루 세 번** 쓰는 동작(TOP 3 승격)이다. **열 번 넘게** 쓰는 동작(배치)은 호버해야 나타난다. 빈도와 시각적 무게가 정확히 뒤집혀 있다.
3. **빠진 정보.** 배치가 끝난 뒤 그 행이 어떻게 되는지 표시가 없어, 이미 놓은 것을 또 놓게 된다.

## 1. D9 — Brain dump 행 재설계 (이번 사이클)

### D9-1. 체크박스 제거, 좌측은 드래그 손잡이로

```
⠿  업체 탐색                              [TOP 3]
⠿ | day3box                              [TOP 3]
⠿  회의준비          끌어서 시간 위로       [TOP 3]   ← 호버
```

- **좌측**: 드래그 손잡이(⠿). 잡아서 우측 그리드의 원하는 시간대에 놓는다.
- **색 막대**: 손잡이 오른쪽. TOP 3만 컬러. (기존 규칙 유지)
- **우측**: TOP 3 배지 토글.

**근거**: "할 일은 시간 위에 놓여야 계획이 된다"는 제품 문장이 그대로 손동작이 된다. 또한 클릭 배치는 시스템이 "다음 빈 슬롯"을 추측하지만, 사용자는 대개 "이건 오후 3시쯤"이라는 의도를 갖고 있다. 드래그는 그 의도를 한 동작으로 표현한다.

**배제한 대안**:
- *행 클릭 = 배치(9a)*: 진단 수정은 동일하나 시간대 지정 불가. 놓은 뒤 다시 끌어야 한다.
- *우측 칩 하나로 통합(9c)*: TOP 3 지정이 제목 앞 번호로 밀려 표적이 작아진다.

### D9-2. 우측 TOP 3 배지는 배치 후에도 유지 ⚠️

배치된 행에서도 `[TOP 3]` 배지를 **없애지 않는다.**

**근거**: D7에서 "강등해도 블록은 유지된다"고 확정했다. 즉 **배치된 상태에서 강등하는 것은 정상 경로**다. 배지가 곧 토글이므로, 배치 후 배지가 사라지면 **강등 경로 자체가 UI에서 사라진다.**

초기 9b 시안은 배치된 행의 우측을 시각(`09:20`)으로 대체해 이 경로를 막고 있었다. 채택하지 않는다.

### D9-3. 시각(`09:20`) 표기 제거

배치된 행에 배치 시각을 표시하지 않는다.

**근거**: 어디에 놓였는지는 **바로 옆 그리드가 이미 말한다.** 좌측 목록이 답해야 할 질문은 "어디에 놓였나"가 아니라 **"아직 뭘 놓아야 하나"**다.

### D9-4. 배치 여부는 **밝기 한 채널로만** (10a)

```
⠿  업체 탐색                    [TOP 3]      ← 미배치: 또렷함
⠿ | day3box                    [TOP 3]      ← 배치됨: 한 톤 옅게
```

- 배치된 행의 **제목 농도를 한 단계 낮춘다.**
- **손잡이는 그대로 남긴다** — 다시 끌어 옮길 수 있어야 한다.
- 호버 문구 분기: 미배치 `끌어서 시간 위로` / 배치됨 `끌어서 옮기기`

**⚠️ 농도 주의**: 시안의 62%는 과할 수 있다. **비활성(disabled)으로 읽히지 않는 선**에서 멈출 것. 여전히 또렷이 읽히고 클릭·드래그 가능해 보여야 한다.

**근거 — 왜 밝기 한 채널인가**: 우측 자리를 **완료 표시(D10)를 위해 비워둬야 한다.** 배치 여부에 우측 표식을 쓰면 완료가 들어갈 자리가 없어진다.

**배제한 대안**:
- **10c(우측에 `■` 표식)** — ⚠️ **반드시 피할 것.** `■`는 6b에서 **그리드 블록의 완료**를 뜻한다. 이를 배치 표시로 쓰면 같은 기호가 좌측=배치, 우측=완료로 갈라지고, D10에서 완료를 놓을 자리가 사라진다.
- **10b·10e(손잡이가 자국으로 변함)** — 배치된 행의 손잡이가 사라져 다시 끌려면 행을 눌러야 한다. 9b를 택한 이유(드래그)를 스스로 훼손한다.
- **10d(미배치에 파선 밑줄)** — 아침에는 전부 미배치이므로 목록 전체에 파선이 깔린다. 계획을 시작하는 순간이 가장 소란해진다.

### D9-5. 목록 순서 고정 — 배치해도 자리를 옮기지 않는다

배치 여부로 목록을 두 묶음(`아직 시간이 없는 것` / `시간 위에 놓인 것`)으로 가르지 **않는다.** 입력 순서를 유지한다.

**근거 세 가지**:

1. **TOP 3가 흩어진다.** 묶음을 가르면 배치된 TOP 3와 미배치 TOP 3가 화면 위아래로 나뉜다. 이 제품에서 가장 중요한 정보가 "오늘의 셋"인데 한눈에 안 들어오게 된다. 더구나 아래 묶음이 흐려지면 **배치를 마친 TOP 3일수록 덜 보인다** — 계획을 완성할수록 핵심이 뒤로 물러나는 구조다.
2. **드래그와 충돌한다.** 항목을 그리드에 놓는 순간 출발지 목록이 재배열된다. 방금 끌어낸 행이 아래로 점프하고 나머지가 한 칸씩 올라온다. 여덟 개를 놓으면 여덟 번 일어난다. 드롭 직후 시선이 돌아갈 자리가 사라진다.
3. **brain dump의 의미가 바뀐다.** 좌측은 "머릿속에 있는 전부"인데, 배치 여부로 가르면 작업 큐가 된다. **쏟아낸 순서가 그날의 사고 흐름**이므로 이를 보존한다.

> **재검토 신호**: 목록이 15줄 이상으로 길어져 "남은 항목 훑기"가 실제로 불편해지면 정렬 옵션을 검토한다. 다만 그때도 **기본값은 입력 순**이어야 한다.

### D9-6. 섹션 헤더에 남은 개수

묶음을 가르지 않고도 "몇 개 남았나"를 얻는다.

```
쏟아내기 · BRAIN DUMP              4개 남음
머릿속을 다 비운다. 개수 제한 없음.
```

## 2. 구현 순서 — 손잡이는 드래그가 동작할 때 노출

**⚠️ 손잡이가 보이는데 드래그가 안 되면 깨진 약속이다.**

좌측 리스트 → 우측 그리드 드래그는 **컨테이너를 넘는 드래그**라 D1(그리드 내부 드래그 생성)보다 비싸다. 특히 그리드가 04–익일 03시로 스크롤되므로, 화면 밖 시간대에 놓으려면 **가장자리 자동 스크롤**이 필요하다.

둘 중 하나로 갈 것:
- **(A)** 드래그까지 한 사이클에 포함
- **(B)** 클릭 배치만 먼저 내고, 드래그가 동작할 때 손잡이를 노출

**판단 요청**: D1의 pointer 로직을 얼마나 재사용할 수 있는지 확인 후 A/B를 제안할 것.

## 3. D10 — 완료 표시 (이번 사이클 아님, 정의만)

완료한 할 일을 **brain dump와 타임박스 양쪽에** 표시한다. **다음 사이클로 미룬다.**

**미루는 근거**: 저녁 기록 시점에 사람이 보는 것은 **그리드**다(블록 위에서 상태를 찍으므로). brain dump는 아침 도구다. 완료를 좌측에 비추는 것은 유용하지만 **현재 사용을 막고 있는 문제가 아니다.** 반면 체크박스 혼동은 매일 발생 중이다.

### 채널 분리 (D9-4가 이를 위해 우측을 비워둔 것)

| 정보 | 채널 |
|---|---|
| TOP 3 여부 | 좌측 색 막대 + 우측 배지 |
| **배치 여부** | **밝기** (D9-4) |
| **완료 여부** | **우측 표식** — 그리드 6b와 **같은 기호** |

그리드에서 쓰는 표식(`◧` 부분 / `■` 완료)을 brain dump에서도 그대로 쓴다. **한 기호가 두 화면에서 같은 뜻**을 갖는다.

### ⚠️ 취소선을 쓰지 않는다
1. 5a에서 강등 표시로 취소선을 **제거**했다. 여기서 되살리면 어휘가 흔들린다.
2. 취소선은 **"지워짐"의 문법**이다. 이 제품에서 완료는 지워지는 것이 아니라 **성취로 남는 것**이며, v1에서 그 자리는 사진으로 채워진다.

## 4. 미결 데이터 정의 — 4건에서 5건으로

003 §3의 4건에 아래가 추가된다.

| # | 미결 사항 | 영향 | 현재 제안 |
|---|---|---|---|
| 1 | `est_min`과 블록 길이 합의 관계 | 3a 라벨, 동작 | 리사이즈가 `est_min`을 갱신하지 않음 |
| 2 | TOP 3 강등 시 블록 유지 | 5a 동작 | **유지** (D7 확정) |
| 3 | `이월`에 목적지 날짜 저장 | 6b 표기 | 저장 안 함 |
| 4 | `부분`에 진행 비율 저장 | 6b 표기 | 저장 안 함 |
| **5** | **task 하나에 블록이 여럿일 때 "완료"의 정의** | **D10 표식** | **모든 블록 done → 완료 / 일부 done → 부분** |

**5번 상세**: 완료는 **블록 단위 상태**인데 brain dump 행은 **task 단위**이므로 자동으로 정해지지 않는다. 예: `day3box`가 1/3·2/3·3/3으로 쪼개져 있고 2/3만 done일 때 행은 무엇인가.

- **채택 제안(보수적)**: 모든 블록 done → `완료`, 일부만 done → `부분`, 없음 → 표시 없음.
- 배제: *하나라도 done → 완료* — 너무 관대해 실제 상태를 왜곡한다.

**D10 착수 전 확정 필요.** 이번 사이클(D9)에는 영향 없다.

## 5. Claude Code 판단 요청

1. **D9 구현 순서 A/B 판단.** D1의 pointer 로직을 리스트→그리드 드래그에 얼마나 재사용할 수 있는가? 가장자리 자동 스크롤 비용은?
2. **현재 체크박스가 TOP 3 토글 외에 다른 동작에 묶여 있는지 확인.** 제거 시 영향 범위.
3. **배치 여부 판정 로직 위치 확인.** 분할 블록이 있을 때 "블록이 하나라도 있으면 배치됨"으로 판정되는가?
4. **D9-4 농도 값은 실물에서 조정할 것.** 62%는 시안 값이며 비활성으로 읽힐 위험이 있다.
5. **범위 이탈 감시 유지.** D10을 이번 사이클에 끌어들이지 말 것. 구현 중 새 추상화·새 테이블·설정 UI가 필요해 보이면 멈추고 먼저 보고할 것.
