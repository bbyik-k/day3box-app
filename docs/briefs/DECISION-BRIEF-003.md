# Decision Brief #003 — 디자인 확정 반영 (002 보충)

> **읽는 순서**: `DECISION-BRIEF-002` → `DESIGN-DECISION-001`(시안 확정) → **이 문서**
> **이 문서의 역할**: 앞 두 문서의 충돌을 해소하고, 어느 쪽에도 없는 결정 3건을 추가한다.
> **002는 폐기하지 않는다.** 002는 실사용 피드백 시점의 기록이고 이 문서는 디자인 확정 시점의 기록이다.
> 아래 명시된 항목만 002를 대체한다.

## 1. 002를 대체하는 항목

### D3 — 고정 시간 블록 시각 처리 → **1b 확정**

002의 D3는 *"안 B를 우선 구현하되, 둘 다 만들어 실제 화면에서 비교한다"* 였다.
**비교 완료. 안 B(막대 없음 · 본문만 옅게)로 확정한다. 빗금안은 구현하지 않는다.**

근거: 그리드의 목적은 "모든 블록을 잘 보이게"가 아니라 **"오늘의 셋이 어디 있는지 즉시 알게"**다. 빗금은 v1 이미지 내보내기를 어수선하게 하고 블록 내 사진과 충돌한다.

**단, 확인 필요**: 1b의 고정 블록은 막대도 배경도 거의 없어 **"빈 시간"과 "확보된 시간"의 구분이 약하다.** 화면에서는 호버로 알 수 있으나 이미지로 내보내면 단서가 사라진다. 아주 옅은 외곽선이나 배경 한 단계를 유지할 것. (상세: DESIGN-DECISION-001 §1)

## 2. 추가 결정 — 002·시안 어디에도 없는 것

### D7. TOP 3 교체 UX (5a) + **강등 시 블록 유지** ⚠️

PRD 7.1에 "교체 UX 필수"가 원칙으로 적혀 있으나 구현 지시가 없었다. 확정한다.

**동작**: 좌측 칼럼 안에서 TOP 3 카드가 그대로 선택 대상으로 전환. 모달 없음.
카드 클릭 = 선택 → 하단 버튼 = 확정. 두 단계.

**⚠️ 가장 중요 — 강등은 블록을 파괴하지 않는다.**

시안(5a·5b) 두 안 모두 *"내려간 하나는 쏟아내기로 돌아갑니다"*, *"10:00 블록은 비워지고"* 로 **강등 = 블록 삭제를 전제하고 있었다. 이는 잘못된 기본값이며 채택하지 않는다.**

TOP 3에서 내려도 그것은 여전히 오늘 할 일이고, 이미 배치까지 되어 있다. 강등은 중요도 재평가지 취소가 아니다.

```
강등 시 변경사항:  tasks.is_top3 = false     ← 이것뿐
blocks:            변경 없음. 그대로 유지
시각적 변화:        좌측 막대 컬러 → 회색
```

블록을 지우면 사용자는 배치를 다시 해야 하고, 실수했을 때 되돌릴 수 없다. **파괴적 기본값을 택할 이유가 없다.**

문구: "쏟아내기로 돌아갑니다" → **"일반 할 일이 됩니다. 배치는 그대로 유지됩니다."**

**카드에 표시할 정보**: `90분 · 08:00 배치됨` / `미배치`. 이미 배치한 것을 내리는 것과 아직 안 놓은 것을 내리는 것은 무게가 다르다.

**소스 확인 필요**: 현재 TOP3 해제 로직이 이미 존재한다면 블록을 지우고 있는지 확인할 것. 지우고 있다면 수정 대상.

### D8. 그리드 배율을 상수로 분리

사진 검토 과정에서 `1시간 = 90px` 배율이 제안되었으나 이는 **사진 높이 확보를 위한 v1 기준**이다.

**v0에는 적용하지 않는다.** 90px/시간이면 06–24시가 1620px로 두 화면 넘게 스크롤해야 하고, 사진이 없는 v0에서는 빈 공간과 스크롤만 늘어난다. 미래 기능을 위해 현재 사용성을 떨어뜨리는 것은 방향이 반대다.

```
PX_PER_HOUR = 60   // v0. 사진 도입 시 90으로 전환
```

**요구사항**: 블록 높이, 눈금 위치, 드래그 좌표↔분 변환이 **모두 이 상수 하나에서 파생**될 것. v1에서 숫자 하나로 전환 가능해야 한다.

**소스 확인 필요**: 배율 관련 숫자가 여러 곳에 하드코딩되어 있는지. 스냅 단위(D5, 10분)와 함께 상수 모듈로 통합할 것.

---

### D6 보충 — 소요시간 칩에 240 / 300분을 추가하지 않는다

칩은 `30 / 60 / 90 / 120 / 180` 다섯 개로 고정한다.

1. **블록 분할(D4)과 충돌한다.** 240분은 우리가 분할하기로 한 바로 그 케이스인데, 칩에 두면 "통으로 잡는 게 정상"이라는 신호가 된다.
2. **척도가 흐려진다.** 칩 7개면 352px 안에서 하나당 30px대로 줄어 눈금이 아니라 목록이 된다.
3. **탈출구가 이미 둘 있다** — ±10 스테퍼, 그리드 리사이즈.

> **재검토 신호**: 실사용에서 **주 1회 이상 180을 고르고 더 늘리는 일이 반복되면** 그때 240 하나만 추가를 검토한다. 300은 그때도 넣지 않는다.

## 3. 미결 데이터 정의 — 1건에서 4건으로

002에서는 `est_min` ↔ 블록 길이 관계 1건만 열려 있었다. 시안 검토 과정에서 **표현이 데이터 정의를 암묵적으로 결정해버리는 일**이 반복되어 4건이 되었다.

| # | 미결 사항 | 영향 | 현재 제안 |
|---|---|---|---|
| 1 | `est_min`(계획 총량)과 블록 길이 합(실제 배치량)의 관계. **리사이즈가 `est_min`을 갱신하는가?** | 분할 블록(3a) 라벨, 동작 | **갱신하지 않음.** 둘의 차이 = 미배치 잔량 |
| 2 | TOP 3 강등 시 블록 유지 여부 | 5a 동작 | **유지** (→ D7에서 확정) |
| 3 | `이월`에 목적지 날짜를 저장하는가 | 6b `→ 9/13` 표기 | 저장 안 함 → **날짜 표기 제거** |
| 4 | `부분`에 진행 비율을 저장하는가 | 6b `60분쯤 했음` 표기 | 저장 안 함 → **`부분`으로 표기** |

**1번은 반드시 먼저 확정해야 한다.** 분할 UI(D4)의 전제이며, 여기가 정해지지 않으면 3a 메타 문구(`180분 중` / `남은 120분`)를 확정할 수 없다. 특히 **미배치 잔량이 있는 경우**(총 180분인데 60+60만 배치) 라벨이 달라져야 한다.

3·4번은 표기를 보수적으로 두면 나중에 되살릴 수 있으므로 급하지 않다.

## 4. 최종 확정 요약 (시각)

| # | 항목 | 확정 |
|---|---|---|
| 1 | 고정 시간 블록 | **1b** 막대 없음 · 본문만 옅게 |
| 2 | 소요시간 입력 | **2a** 한 줄 칩 + 아래 ±10 |
| 3 | 분할된 블록 | **3a** 1/2 · 2/2 표기 (`↳` 제거) |
| 4 | 드래그 생성 | **4a** 고스트 블록 안에 정보 (하단 배치 시도) |
| 5 | TOP 3 교체 | **5a** 제자리에서 자리 내주기 |
| 6 | 블록 상태 | **6b** 우측 인쇄 표식 (날짜·비율 표기 제거) |

**관통 규칙 두 가지 — 개별 항목보다 우선한다.**
1. **색은 TOP 3에만.** 위계는 `컬러 막대(TOP3) → 회색 막대(일반) → 막대 없음(고정)`. 막대의 유무가 "이건 일인가"의 답이다.
2. **블록 본문은 비워둔다.** v1에서 사진이 들어갈 자리다. 상태·진행도를 본문 채움으로 표현하지 않는다.

각 항목의 상세 근거와 확인 사항은 `DESIGN-DECISION-001` 참조.

## 5. Claude Code 판단 요청

1. **미결 1번(`est_min` ↔ 블록 길이)을 소스와 대조해 먼저 확정할 것.** 현재 리사이즈가 `est_min`을 갱신하고 있는가? 갱신한다면 분할 도입 시 정합성이 깨진다.
2. **D7 — 현재 TOP3 해제 로직이 블록을 지우고 있는지 확인할 것.** 지우고 있다면 수정 대상.
3. **D8 — 배율·스냅 관련 숫자의 하드코딩 여부 확인.** 상수 모듈로 통합 제안.
4. **작업 순서 제안.** 002 §8의 순서 제안은 유효하나, D7·D8이 추가되었으므로 의존 관계를 다시 볼 것.
5. **범위 이탈 감시 유지.** 구현 중 새 추상화 계층·새 테이블·설정 UI가 필요해 보이면 멈추고 먼저 보고할 것.
