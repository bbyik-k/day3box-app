## 1. 제품 규칙 — 개별 UI보다 우선한다

이 넷을 위반하는 구현은 화면이 예뻐도 틀린 것이다.

1. **할 일은 시간 위에 놓이지 않으면 계획이 아니다.** 배치되지 않은 할 일은 "계획됨" 상태를 가질 수 없다.
2. **TOP 3는 하드 제한 3개.** 4번째를 올리려면 하나가 자리를 내줘야 한다. 4개를 허용하는 코드 경로가 있으면 안 된다.
3. **색은 TOP 3에만.** 색이 들어가는 곳은 블록 좌측 4px 세로 막대뿐. 위계는
   `컬러 막대(TOP 3) → 회색 막대(일반 할 일) → 막대 없음(고정 시간)`.
   **막대의 유무가 "이건 일인가"의 답이다.** 블록 본문은 항상 중립 회색.
4. **블록 본문은 비워둔다.** v1에서 그 시간의 사진이 들어갈 자리다. 상태·진행도를 본문 채움(배경 그라디언트 등)으로 표현하지 말 것.

**실패를 전시하지 않는다**: 이월(moved)에 빨간색·취소선·경고 아이콘 금지. 이월은 심판이 아니라 "내일 대기 중"이다. 하루가 무너진 날의 화면도 다시 열고 싶어야 한다.

## 2. 그리드 — 상수 하나에서 전부 파생

```
HOUR_PX = 60          // v0. v1(사진)에서 90으로 바꾸면 전부 따라온다
MIN_PX  = HOUR_PX / 60   // = 1
SNAP_MIN = 10            // 모든 시각은 10분 배수
DAY_START = 6 * 60       // 06:00
DAY_END   = 22 * 60      // 22:00  → 그리드 높이 960px

top    = (startMin - DAY_START) * MIN_PX
height = durationMin * MIN_PX - 1      // -1 = 블록 사이 1px 홈
```

**하드코딩 금지.** 눈금 위치·블록 높이·드래그 계산이 모두 이 식을 통과해야 한다. v1 전환이 숫자 하나 바꾸기여야 한다.

- 눈금선은 **정시에만** 그린다(10분 눈금은 드래그 중에만 등장 — §6).
- 블록은 겹치지 않는다. 레인/가로 오프셋 배치는 없다. 겹치는 자리에는 놓이지 않는다.

### 블록 높이별 내용 3단계

| 길이 | 높이 | 클래스 | 내용 |
|---|---|---|---|
| 45분 이상 | ≥44px | `.p2` | 제목 + 메타 2줄 |
| 25–44분 | 24–43px | `.p1` | 한 줄 (제목 좌, 메타 우) |
| 10–24분 | 9–23px | `.p0` | 초경량 한 줄, 11px |

높이로 자동 선택할 것. 30분(29px)에서도 제목이 반드시 읽혀야 한다.

## 3. 화면 구성

좌우 2단, 좌측 **352px** 고정 + 우측 유동, 사이는 여백으로만 구분(세로선/카드 금지).
최대폭 1200px. 데스크톱 우선이지만 터치 타깃은 36px 이상 유지(모바일 확장 대비).

### 3-1. 아침 계획 (`captures/01-morning-plan.png`)

좌측 = 생각하는 공간 / 우측 = 시간 그리드. 사용 흐름은 **좌 → 우**.

**좌측 상단 · 쏟아내기**
- 개수 제한 없음. 체크박스 + 이름, TOP 3인 항목에 `.tag.tag-outline` "TOP 3" 배지.
- **고정 시간 블록(식사·이동·휴식·약속)은 여기 나타나지 않는다.** 그리드에만 존재한다.
- 마지막에 파선 "＋ 할 일 추가…" 행.

**좌측 하단 · TOP 3 카드 3장**
- 카드마다: 슬롯 라벨(`01 · 집중` 등) / 우측 상단에 현재 소요시간 / 제목 / 프리셋 칩 / ±10 스테퍼.
- 칩은 `30 / 60 / 90 / 120 / 180` **한 줄 5개**. 선택된 것만 `.chip-on`(검정 채움).
- **자유 숫자 입력 없음.** 240·300 칩도 추가하지 않는다(근거는 결정문 §2).
- ±10은 보조. 프리셋 밖의 값(예: 70분)은 칩이 하나도 채워지지 않고 상단 숫자만 바뀐다.
- 셋이 차면 마지막에 "셋이 찼다 · 4번째는 하나가 자리를 내주면 올라온다" 파선 안내.

**우측 · 타임박스 그리드**
- 헤더에 3위계 범례(오늘의 셋 / 나머지 할 일 / 확보한 시간).
- 현재 시각선: 1.5px 마젠타 실선 + **우측 끝**에 "지금 14:30" 칩. (좌측은 블록 텍스트와 겹친다.)

### 3-2. TOP 3 교체 (`captures/02-top3-swap.png`)

셋이 찬 상태에서 4번째를 올리려 할 때. **모달이 아니다** — 좌측 칼럼 제자리에서 일어난다.

- 상단에 "올릴 것" 블록(검정 4px 막대 + 이름).
- 안내 문구: **"어느 자리에 넣을까요? 내려간 하나는 일반 할 일이 됩니다. 배치는 그대로 유지됩니다."**
- TOP 3 카드 3장이 선택 대상(`.pick`)으로 바뀐다. 카드마다 `180분 · 08:00 배치됨` 또는 `90분 · 미배치` 표시 — 이미 배치한 것을 내리는 것과 아직 안 놓은 것은 무게가 다르다.
- 선택된 카드: 옅은 시안 틴트 + 제목 옅게 + `↑ 은행 업무가 이 자리로`. **취소선 금지.**
- 흐름은 두 단계뿐: **카드 클릭 = 선택 / 하단 "바꾸기" = 확정.** 카드 안에 버튼을 두지 말 것.
- "안 됨 / 초과 / 제한" 같은 어휘 금지. 거절이 아니라 선택이다.

**⚠️ 강등은 블록을 파괴하지 않는다.** `is_top3 = false` 하나만 바뀐다.
블록은 그 자리에 그대로 있고 **막대 색만 컬러 → 회색**으로 바뀐다. 블록을 지우면 사용자가 배치를 다시 해야 하고 되돌릴 수 없다.
(우측에 이 결과를 미리 보여주는 12–17시 축소 그리드가 있다.)

### 3-3. 저녁 기록 (`captures/03-evening-record.png`)

**좌측**
- 완료 / 부분 / 이월 개수 3개 숫자.
- TOP 3 결과 목록: 색 막대 + 이름 + 상태 표식 + 상태 텍스트.
- 선택된 블록의 상태 기록 카드: `.seg` 세그먼트 컨트롤 `완료 / 부분 / 이월`.
- 한 줄 회고 textarea.

**우측** — 같은 그리드에 상태 표식이 붙는다. 선택된 블록은 `box-shadow:0 0 0 2px var(--color-accent)`.

## 4. 블록의 네 상태 (확정: 우측 인쇄 표식)

| 상태 | 표식 | 클래스 | 라벨 |
|---|---|---|---|
| 계획됨 | □ 윤곽 | `.mk.mk-plan` | `계획됨` |
| 완료 | ■ 채움 | `.mk.mk-done` | `완료` |
| 부분 | ◧ 절반 | `.mk.mk-part` | `부분` |
| 이월 | ▨ 빗금 | `.mk.mk-move` | `이월` |

- **본문 무게는 네 상태 모두 같다.** 상태는 우측 11px 표식 + 메타 텍스트로만 말한다. 옅게 처리하거나 본문을 채우지 말 것.
- **이월에 목적지 날짜를 쓰지 말 것** (`→ 9/13` 금지). 스키마에 목적지 날짜가 없다. 이월은 다음 날 아침 좌측 "어제에서 이월"에서 끌어오는 방식이다.
- **부분에 비율을 쓰지 말 것** (`60분쯤 했음` 금지). 스키마가 비율을 저장하지 않는다. 그냥 `부분`이 정직하다.
- 위 둘은 결정문 §8의 미결 3·4번이 확정되면 되살릴 수 있다.

## 5. 분할된 블록 (확정: 1/2 · 2/2 표기)

긴 작업이 고정 블록(점심 등)으로 끊길 때. **별개의 두 작업으로 보이면 안 된다.**

- 같은 제목 + 같은 색 막대 유지.
- 제목 뒤에 `1/2` `2/2`를 400 weight · 11px · 옅은 회색으로. 조각이 셋 이상이면 `1/3 2/3 3/3`.
- **잘린 변의 테두리를 없앤다**: 첫 조각은 `border-bottom:0` + 하단 라운드 제거, 두 번째 조각은 `border-top:1px dashed` 색 막대색 55% + 상단 라운드 제거.
- 두 번째 조각 본문은 **4px 안으로 들여쓴다**(`padding-left:14px`) — 1b에서 테두리를 거의 없앴으므로 파선만으로는 약하다.
- **`↳` 기호를 쓰지 말 것.** 표기가 이미 "앞이 있다"를 전달하고, 한글 UI에서 낯설다.
- 색 막대를 고정 블록 구간까지 관통시키지 말 것 — 고정 블록에 컬러 막대가 붙은 것처럼 보여 §1의 규칙 3이 무너진다.

**⚠️ 메타 문구(`총 180분 중`)는 결정문 §8-1이 확정되기 전까지 잠정이다.** `est_min`과 블록 길이 합의 관계, 특히 미배치 잔량이 있는 경우의 라벨이 미정. 구현은 하되 문구는 상수 하나로 빼둘 것.

## 6. 드래그로 블록 생성 (확정: 고스트 블록 안에 정보)

빈 곳을 눌러 아래로 끄는 동안:

- 10분 단위 스냅. **10분 눈금(10px 간격 옅은 선)은 드래그 중에만** 나타난다.
- 고스트: 1px 파선 시안 테두리 + 시안 9% 배경.
- **정보는 고스트 블록 하단(끄는 쪽)에** — 소요시간(좌, 굵게) + 시각 범위(우). 하단 가장자리에 2px 시안 실선을 둬 "여기가 커서"를 표시. 상단에 두면 커서와 시선이 갈라진다.
- 20px 이하(20분 이하)에서는 한 줄로 접힌다. **최소 10분(10px) 상태를 반드시 테스트할 것** — 한 줄이 안 들어가면 블록 밖 표시로 대체.
- 놓으면 이름 입력으로 이어진다.
- **겹침(배치 불가) 표시에 크림슨을 쓰지 말 것.** 이미 TOP 2 막대와 현재 시각선이 그 색이다. 색이 아닌 수단(파선 → 실선, 채도 낮춘 회색 등)으로 구분할 것.
- 우선순위 낮음: 몇 초만 존재하고 이미지에 절대 나오지 않는 상태다. 시간을 많이 쓰지 말 것.

## 8. 시작 전 확인할 것 (코드로 확정하지 말고 물어볼 것)

결정문 §8의 미결 데이터 정의 4건. **1·2번은 동작에 직결되므로 반드시 먼저 확정.**

1. `est_min`(계획 총량)과 블록 길이 합(실제 배치량)의 관계 — 리사이즈가 `est_min`을 갱신하는가? *제안: 갱신하지 않음. 차이가 "미배치 잔량".*
2. TOP 3 강등 시 블록 유지 여부 — *제안: 유지. `is_top3=false`만 변경.* (§3-2에 이미 반영)
3. `이월`에 목적지 날짜를 저장하는가 — *현재 저장 안 함 → 표기 없음.*
4. `부분`에 진행 비율을 저장하는가 — *현재 저장 안 함 → `부분`으로만 표기.*

## 9. 검수 체크리스트

- [ ] 30분 블록에서 제목이 읽히는가
- [ ] 10분 블록이 배치·표시되는가
- [ ] 하루가 블록으로 꽉 찬 상태에서 **컬러 막대 3개가 즉시 눈에 들어오는가**
- [ ] 고정 블록이 "빈 시간"과 구분되는가 (호버 없이, 정지 이미지에서도)
- [ ] 현재 시각 칩이 블록 텍스트를 가리지 않는가
- [ ] TOP 3에 4개가 들어갈 수 있는 경로가 없는가
- [ ] 강등 후 블록이 그 자리에 남아 있고 막대만 회색인가
- [ ] 다섯 중 넷이 이월된 날의 화면이 "실패 보고서"로 보이지 않는가
- [ ] 11px 표식 4종이 구분되는가 (이미지로 내보내 압축된 뒤에도)
- [ ] `HOUR_PX`를 90으로 바꾸면 전부 따라오는가
